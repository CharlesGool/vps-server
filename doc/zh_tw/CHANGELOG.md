## v1.1.0 — 2026-09-19

### Added

- **由主控台管理的連接埠轉發功能。** 全新的「連接埠轉發」頁面，讓你可以把這台
  主機上的公開 TCP/UDP 埠，轉發到透過 Tailscale 或區域網路連到的另一台裝置
  ——適用於這台主機擁有公開 IP、而目標裝置沒有的情況。可以在主控台中新增、
  啟用、停用與刪除轉發規則；每一條規則在套用之前，都會先與這次安裝已經在
  使用的每一個埠（主控台、公開頁面、iperf3、anytls）核對，避免衝突。這些
  規則底層由 `iptables` 的 DNAT + MASQUERADE 實作，並且每次服務啟動時都會
  自動重新套用，因此重新啟動服務或重新開機時，每一條已啟用的轉發規則都會
  直接恢復，而不會遺失。`net.ipv4.ip_forward` 會在第一次需要用到時自動開啟。
  將 `VPSSRV_PORTFWD_ENABLE` 設為 `0`，即可從某次安裝中完全移除此功能。

## v1.0.4 — 2026-09-12

### Changed

- 安裝程式結尾的摘要現在會印出機器實際的 IP 位址，而不是先前那個必須手動
  代換過才能讓網址可用的 `<this-server>` 占位符。核心實際會用來對外連線的
  那個位址，會顯示在公開頁面與主控台那兩行上；在有多個網路介面的機器上，
  其餘位址會列在下方，並各自標明所屬介面，因此像只能透過 ZeroTier 或
  Tailscale 連到的節點，也能直接看到而不必用猜的。若讀不到任何位址，仍會
  照舊印出舊的占位符，避免原本一切正常的安裝，因為這種外觀上的小事而失敗。

## v1.0.3 — 2026-09-12

### Fixed

- 即使套用了 v1.0.2 的修正，`install_iperf3()` 仍有可能失敗。`apt-get update`
  可能回報成功，但 `security.debian.org` 的 CDN 卻回傳一份過期的套件索引，導致
  緊接著執行的 `apt-get install` 在嘗試抓取那個索引宣稱存在的 `.deb` 時直接
  404——這是在一台真實主機上從 v1.0.1 升級到 v1.0.2 時實際發生的情況。單獨重試
  一次 `update` 並不能可靠地解決問題，因為重試仍有可能打到同一個過期的邊緣
  節點。安裝程式現在會把 update 和 install 這一整組動作一起重試，最多重試
  3 次，只要後續某一次剛好打到已同步的鏡像來源，就能恢復正常。
- README 的 `## Install` 章節裡仍留有未填的範本佔位符——一個原樣照抄的
  `<repo-url>`，以及一個 `v0.1.0` 範例標籤，而本專案從未真正發布過這個名稱的
  版本。兩者現在都已改成真實的值：本專案實際的 GitHub URL 以及目前的發布標籤。

## v1.0.2 — 2026-09-12

### Fixed

- `install.sh` 有可能在安裝 iperf3 時悄悄失敗：它把 apt 的 update 和 install
  兩個步驟串在一起執行，並把所有輸出都丟棄，因此只要有一個不相干的損壞來源
  ——例如一個過期的第三方 `.list` 檔案，這正是在一台真實 VPS 上實際發生的情況
  ——就會導致 update 步驟失敗，進而完全跳過 iperf3 的安裝，而且完全看不出原因。
  現在會重試 update，並且不論 update 是否成功都會嘗試執行 install，同時當
  install 真正失敗時，不再隱藏 apt 自身的錯誤輸出。

## v1.0.0 — 2026-09-12

首次發布。本專案整合了兩個既有專案——一個帶密碼保護的 VPS 測速控制台，以及一個
sing-box `anytls` 安裝程式——並新增了兩者原本都沒有的兩項能力：一個隨需開啟的
iperf3 時間窗，以及一個公開頁面，讓任何人都能檢查你的 IP 在網路上是否有回應。

### Added

- **80 和 443 埠上的公開可達性頁面，無需登入。** 把 IP 給任何人；只要頁面能渲染
  出來，就表示你的 web 埠從對方所在的位置是可達的。頁面會回報對方的來源位址、
  伺服器時鐘，以及對方是從哪個埠、哪種協定進來的——除此之外不透露主機的任何
  其他資訊。同時服務兩個埠是刻意設計的：這樣才能區分「主機不可達」和
  「443 這個特定埠被擋住了」這兩種情況。
- **隨需開啟的 iperf3 時間窗。** 控制台會開啟一個有時限的時間窗；`iperf3`
  只在窗口期間執行，會在目前生效的防火牆上開放對應埠，並在窗口到期時——不論是
  應要求關閉，還是服務本身停止——把兩者一併關掉。沒有「一直開著」這個選項，
  因為一台常駐的 iperf3 伺服器會讓任何陌生人跑滿你的上行頻寬。窗口開啟期間，
  公開頁面會顯示這個訊息，讓測試者知道何時可以連線。
- **瀏覽器測速與訪問記錄**，皆在控制台內提供：使用 LibreSpeed 引擎進行的上傳/
  下載測速，以及從核心連線表讀取的、任意埠上每一筆連入 TCP 連線的記錄——不只
  限於 HTTP。
- **anytls 代理模組。** 搭配自簽憑證的 sing-box，並啟用 BBR。控制台會顯示節點
  的埠、密碼與 SNI，提供附一鍵複製按鈕的 Clash 設定條目與 `anytls://` 連結，並
  可以輪換認證資訊。
- **可選模組的安裝程式。** web、iperf3 與 anytls 各自獨立選擇，可互動式選擇，也
  可透過 `VPSSRV_MODULES` 用於無人值守安裝。遇到埠已被其他程序占用時會選擇拒絕
  安裝，而不是硬搶；在非 x86-64 架構上則會跳過 anytls，而不是安裝一個根本跑不
  起來的執行檔。
- **可感知既有安裝的重新安裝。** 重新執行安裝程式時會偵測到既有安裝，提供保留
  其設定的選項，重放記錄在 service unit 中的設定值，保留 anytls 節點的認證資訊，
  並只詢問既安裝版本當初沒有的那些設定項。早於這套記錄機制的舊安裝，則透過讀取
  磁碟上的模組清單來處理。
- **三種介面語言**——英文、簡體中文、繁體中文——在安裝時選擇，之後每次造訪皆可
  切換，並會記住選擇。
- **離線安裝。** sing-box 執行檔隨程式碼庫一併提供，因此安裝除了發行版自身的套件
  鏡像來源之外，不需要任何其他東西。

### Notes

- 整個專案採用 GPL-3.0 授權，因為它重新散布了採用 GPL-3.0 授權的 sing-box
  執行檔。各元件的授權條款以及 GPL 要求提供的對應原始碼連結，都列在
  `THIRD_PARTY_NOTICES.md` 中。
- 443 上的 TLS 是自簽憑證：沒有網域，也沒有 ACME。瀏覽器發出警告仍然能證明該埠
  有回應，而這正是那個頁面存在的目的所要解決的問題。
- iperf3 JSON 輸出中的 `mean_rtt` 來自核心的 `TCP_INFO`，因此 Linux 用戶端會回報
  往返時間，而讀不到這項資訊的用戶端——例如在 Windows 上透過 Cygwin 執行的
  iperf3——就只會回報傳輸量。UDP 模式（`-u`）在任何情況下都能提供抖動與丟包率
  資訊。
- anytls 模組僅支援 x86-64。web 與 iperf3 模組則與架構無關。
