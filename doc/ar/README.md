## مقدمة

حزمة بوحدات قابلة للاختيار لخادم VPS يعمل بنظام Debian/Ubuntu: صفحة عامة لفحص إمكانية الوصول إلى منافذ الويب، ولوحة للمشغّل لاختبارات السرعة وتسجيل الاتصالات، ونافذة iperf3 عند الطلب، وعُقد وكيل sing-box. يضيف v3.0.0 عُقدًا مُدارة وسياسات مرور ووصولًا بلا كلمة مرور من عناوين IP خاصة وخياري المظهر الفاتح والداكن. تضم الحزمة أيضًا مثبّتَي frps وLucky التجريبيين. انظر [الحالة الراهنة وحدود القبول][local-link-001].

## الوظائف

- **إثبات إمكانية الوصول للجميع.** صفحة بسيطة عمدًا على المنفذين **80** و
  **443**، بلا تسجيل دخول. أعطِ شخصًا عنوان IP؛ فإذا ظهرت الصفحة، كانت منافذ الويب لديك قابلة للوصول من موقعه. تعرض عنوان IP المصدر لديه، ووقت الخادم، والمنفذ والبروتوكول اللذين وصل عبرهما، ولا تعرض أي معلومات أخرى عن المضيف.
- **قياس معدل النقل من المتصفح.** تُجري اللوحة على منفذ عالٍ عشوائي محفوظ اختبارات الرفع والتنزيل باستخدام LibreSpeed. يمكن الدخول بكلمة مرور المدير أو عنوان IP خاص لشبكة محلية أُضيف صراحةً. يظهر زر الدخول عبر IP دائمًا؛ ويُوجَّه الزائر غير المسموح له إلى الدخول بكلمة المرور ثم إضافة عنوان خاص في إعدادات الوصول. تتطلب إعدادات الأمان تحققًا حديثًا بكلمة مرور المدير قبل عرض قائمة العناوين أو قبول التعديلات. تقبل القائمة عناوين IPv4 الخاصة أو IPv6 المحلية الفريدة، عنوانًا منفردًا لكل إدخال، ويمكن تعطيل الدخول عبر IP دون حذف القائمة. يؤدي تغيير كلمة المرور إلى إبطال الجلسات الحالية. تتيح صفحة الإعدادات العامة اختيار المظهر واللغة مباشرة؛ وتستلزم إعدادات الأمان إعادة التحقق بكلمة مرور المدير بعد انتهاء صلاحية التحقق.
- **قياس معدل النقل وزمن الاستجابة عبر iperf3 عند الطلب.** تفتح اللوحة نافذة محددة المدة؛ لا يعمل `iperf3 -s` إلا خلالها، ويتوقف تلقائيًا عند انتهائها. يحصل المختبِر على معدل النقل من iperf3، ويحصل أيضًا على زمن الذهاب والإياب على عميل Linux من `mean_rtt` في مخرجات `--json`؛ يأتي هذا الحقل من `TCP_INFO` في النواة، ولا يظهر على العملاء الذين لا يمكنهم قراءته، ولا سيما iperf3 تحت Cygwin على Windows. يضيف وضع UDP (`-u`) التذبذب وفقد الحزم على جميع المنصات. تعرض اللوحة الحالة والمنفذ كلًا على حدة؛ يمكن تغيير المنفذ عندما تكون نافذة الاختبار مغلقة، ويبقى الإعداد بعد إعادة تشغيل الخدمة.
- **تسجيل المتصلين.** كل اتصال TCP وارد، على أي منفذ لا HTTP فقط، يُقرأ من `/proc/net/tcp[6]` ويُخزّن في SQLite مع الاحتفاظ بأحدث 1000 اتصال.
- **يوفّر وكيل anytls.** يستخدم sing-box شهادة ذاتية التوقيع وBBR. تعرض صفحة `/proxy` المحمية حالة العقدة وحركة بياناتها وإعدادات الاتصال القابلة للتعديل؛ وعند توفر عنوان LAN خاص، تعرض أيضًا رابط استيراد بنقرة واحدة إلى Clash Meta for Android ورمز QR. ويمكن أيضًا نسخ عنوان URL للاشتراك.
- **يوفّر أي مجموعة من وكلاء vmess/vless/trojan/shadowsocks.** تشارك عملية sing-box إضافية الملف التنفيذي المضمّن مع anytls. يبدأ كل بروتوكول مثبّت بعقدة مرقّمة؛ وتتيح اللوحة إنشاء عقد إضافية لأي بروتوكول مثبّت وحذف كل عقدة على حدة. لكل عقدة حدّ حركة بيانات بوحدة GiB، ومحرّران منفصلان للاتصال والحدود، وأداة إعادة ضبط عشوائي، وخيار استيراد Clash Meta نفسه عبر LAN فقط. يحتوي عنوان URL للاستيراد على رمز مبهم ويُبطَل عند تغيير اسم العقدة أو إعدادات اتصالها. لا تقدّم المنافذ العامة إعدادات الوكلاء. يمكن إدخال كلمة مرور العقدة الجديدة أو مفتاح/UUID البروتوكول يدويًا أو ترك الحقل فارغًا لتوليدها عشوائيًا؛ قيمة SNI الافتراضية لعقد TLS هي `www.bing.com`. تعرض صفحة العقد عناوين واجهات الشبكة وTailscale. تدعم كل عقدة حدَّ سرعة مستقلًا للرفع والتنزيل بوحدة Mbps. عند بلوغ حد حركة البيانات بوحدة GiB يمكن تحديد السرعة في الاتجاهين عند 1 Mbps أو منع الاستخدام. تُصفّر حركة الفترة كل عدد محدد من الأيام أو الأشهر أو السنوات. ويمكن تحديد مدة صلاحية اختيارية تمنع الاستخدام عند انتهائها. ويمكن أيضًا نسخ رابط الاشتراك المحلي.

تعرض صفحة FRPS المحمية بتسجيل الدخول حالة خدمة الخادم المحلي وعناوين واجهاته وإعدادات الاتصال، مع إخفاء المنفذ والرمز إلى أن يطلب المستخدم إظهارهما. يمكن تعديل منفذ FRPS ورمزه في الصفحة نفسها، وتشغيل الخدمة أو إيقافها. تعرض صفحة FRPC المنفصلة مثيلات العميل المحلي في بطاقات، مع عنوان IP مخفي ومؤشر اتصال يعتمد على مقبس TCP مُنشأ فعليًا. ينفّذ زر اختبار الاتصال تسجيل دخول FRPC مستقلًا باستخدام الخادم والمنفذ والرمز المحفوظة. تكشف صفحة المثيل عنوان IP أو الرمز عند الطلب، وتعرض نوع كل وكيل TCP/UDP وعنوان IP المحلي والمنفذ المحلي والمنفذ البعيد قبل تحريره. يبقى المستخدم في صفحة المثيل بعد الحفظ؛ ويُتحقق من الملف وتُستعاد الإعدادات السابقة عند الفشل. تتطلب إجراءات FRP جلسة مسجّل دخول؛ أما التحقق الحديث بكلمة مرور المدير فيخص إجراءات إعدادات الأمان، مثل تغيير كلمة المرور والوصول عبر IP دون كلمة مرور. لا يقبل محرر الحقول إلا إعدادات TCP/UDP البسيطة المعتمدة على الرمز، ولا يغيّر ملفات TOML الخاصة بـFRPC التي لا يستطيع تمثيلها. لا تعرض اللوحة الحالة الحية لمثيلات FRPC على أجهزة أخرى. تفحص صفحة الوحدات الملف التنفيذي المحلي لـFRPC وقالب `frpc@.service` كلًا على حدة، بصرف النظر عن وجود ملفات إعداد المثيلات. تعرض خيار التثبيت إذا غاب أيّ منهما، ورابط إنشاء مثيل إذا كان FRPC مثبتًا بلا مثيلات. يستخدم التثبيت أصل FRPC v0.71.0 مع بصمة تحقق ثابتة، ولا ينشئ اتصالًا أو مستمعًا. يسجل سجل الوحدة التنزيل والتحقق. للتثبيت دون اتصال، نزّل [frpc-0.71.0-linux-amd64](https://github.com/CharlesGool/vps-server/releases/download/v4.0.0/frpc-0.71.0-linux-amd64) (16,593,080 بايت؛ SHA-256 `f79fff8de3089ec711ff8bdd4b73e00dfe491a1c3d754983c8b0f8d58c21b068`) وضعه في `~/apps/vps-server/vendor/frp/frpc` قبل اختيار التثبيت. تتحقق المهمة من البصمة نفسها سواء نُزّل الملف أو وُضع يدويًا. يوقف إلغاء التثبيت مثيلات FRPC المحلية، وينسخ إعداداتها احتياطيًا داخل `data/`، ويحتفظ بملفات الإعداد لإعادة التثبيت لاحقًا.

الوحدات القابلة للاختيار هي web وiperf3 وanytls وproxy وfrps وLucky. تظل وحدتا frps وLucky تجريبيتين؛ ولم يُقبل سلوكهما على مضيف حقيقي لهذا الإصدار.

**ما ليس من الأهداف:** لا ACME ولا أسماء نطاقات (الشهادة على 443 ذاتية التوقيع عمدًا)؛ ولا iperf3 دائم التشغيل؛ ولا وكيل عكسي أو حاويات. لا تكشف الصفحة العامة مطلقًا عن اسم المضيف أو النواة أو مدة التشغيل أو قائمة الخدمات أو إعدادات الوكيل. لا يحل هذا المشروع محل `vps-webserver` أو `Anytsl-Serve`؛ إذ يستمر صيانتهما بصورة مستقلة وتُضمّن شفرتهما هنا بدلًا من دمجهما فيه.

## المتطلبات

- النظام: Debian 11+ أو Ubuntu 20.04+ مع systemd، والتشغيل بصلاحيات root.
- بيئة التشغيل: Python 3.9+ (يكفي `python3` الخاص بالتوزيعة؛ لا توجد تبعيات Python يلزم تثبيتها).
- البنية: أي بنية لوحدتي web وiperf3؛ و**x86-64 فقط** لوحدات anytls وproxy وfrps وLucky، لأن الملفات التنفيذية المضمّنة تستهدف amd64.
- لوحدة web على منافذها العامة الافتراضية، **يجب** أن يكون المنفذان 80 و443 متاحين؛ يرفض المثبّت التثبيت بدلًا من مزاحمة nginx أو Apache أو Caddy أو `vps-webserver`.
- الخدمات الخارجية: لا شيء وقت التشغيل. يحتاج التثبيت إلى مرآة حزم التوزيعة؛ وتستخدم ملخصات العقد عناوين واجهات الشبكة وTailscale عند توفره دون استعلام خارجي عن عنوان IP العام.
- الحد الأدنى: النظام وبيئة التشغيل والبنية والمنافذ المتاحة المذكورة أعلاه. لم تُسجّل متطلبات إضافية موصى بها للعتاد؛ ويمكن لخادم VPS بسعة قرص تقارب 150 MB استيعاب الملف التنفيذي المضمّن.

## التثبيت

تثبيت سريع بسطر واحد (أحدث وسم إصدار، دون متغيرات إعداد):

```bash
git clone --branch v4.0.0 --depth 1 https://github.com/CharlesGool/vps-server.git vps-server && cd vps-server && bash deploy/install.sh
```

خطوة بخطوة، مع الإعداد:

```bash
# استنسخ وسم إصدار؛ فقد يحتوي الفرع الافتراضي على تغييرات لم تُنشر بعد.
# اعرض وسوم الإصدارات: `git ls-remote --tags https://github.com/CharlesGool/vps-server.git`
git clone --branch v4.0.0 --depth 1 https://github.com/CharlesGool/vps-server.git vps-server
cd vps-server
cp .env.example .env   # اختياري — لكل متغير قيمة افتراضية صالحة
bash deploy/install.sh
```

يسأل `deploy/install.sh` عن الوحدات المراد تثبيتها، ولغة الواجهة، وحماية اللوحة بكلمة مرور، والمنافذ المستخدمة. يتضمن وسم v4.0.0 الوحدات الست كلها القابلة للاختيار؛ وتظل frps وLucky تجريبيتين.


### الإعداد الأول

يتوفر مسار الإعداد التالي في v4.0.0. على تثبيت جديد من Debian أو Ubuntu، استنسخ وسم الإصدار وشغّل `bash deploy/install.sh` من طرفية بصلاحيات root. دليل التطبيق الافتراضي لحساب root هو `~/apps/vps-server`؛ ويمكن اختيار دليل آخر بواسطة `PREFIX`.

يفتح المثبّت صفحة إعداد مؤقتة عبر HTTPS على منفذ متاح عشوائي، ويطبع عنوانها وبصمة الشهادة وكلمة مرور عشوائية تُستخدم مرة واحدة في الطرفية. تنتهي صلاحية الصفحة بعد خمس دقائق إذا لم يُجرَ اختيار. سجّل الدخول فيها واختر الوحدات المطلوب تثبيتها؛ وحدة Web إلزامية للإعداد عبر المتصفح. لا تظهر خيارات بروتوكولات الوكيل إلا عند اختيار عقد الوكيل. بعد إرسال الاختيارات، حدّث صفحة الإعداد لمتابعة التقدم. عند انتهاء التثبيت وتوفر عنوان واجهة صالح للمضيف، تعرض الصفحة رابط لوحة التحكم؛ وإلا فاستخدم العنوان المطبوع في الطرفية. تطبع الطرفية عنوان لوحة التحكم وكلمة مرورها الدائمة؛ كلمة مرور الإعداد المؤقتة لا تصلح للدخول إلى اللوحة. يُغلق المستمع المؤقت ويُحرّر منفذه بعد مهلة الإكمال.

من لوحة التحكم، افتح **الإعدادات ← الوحدات**. تتيح جلسة تسجيل الدخول العادية إدارة هذه الوظائف التشغيلية؛ ويبقى التحقق بكلمة المرور مطلوبًا لإعدادات الأمان. تضم قائمة الوحدات اختبار السرعة، وiperf3، وعقد الوكيل، وFRPS، وFRPC، وتحويل المنافذ، والزوار الأخيرين، وسجل التغييرات، والإعدادات. لا تظهر أوامر التثبيت والإزالة إلا للوظائف القابلة للتثبيت المستقل. قبل إزالة إحداها، يحفظ المساعد أرشيفًا خاصًا لإعداداتها داخل `$PREFIX/data`؛ وتعرض صفحة الوحدات آخر سجل للمهمة. تُثبّت الوحدات الاختيارية من ملفات تطابق الإصدار داخل `$PREFIX/installer-source`. لكل بطاقة في الصفحة الرئيسية، عدا الإعدادات، مفتاح تشغيل مستقل. يتحكم مفتاح عقد الوكيل في AnyTLS وبروتوكولات الوكيل الأخرى مع الاحتفاظ بسجلات العقد، ولا يبدأ خدمة إذا لم توجد عقد مفعّلة. يعيد مفتاح FRPC تشغيل المثيلات التي كانت تعمل قبل إيقافه. يحتفظ تحويل المنافذ بالقواعد المحفوظة عند إيقافه، ويعيد تطبيق القواعد المفعّلة عند تشغيله. يجري التثبيت في مهمة systemd مستقلة، وقد يعيد تشغيل خدمة Web لفترة وجيزة. إذا تعذر الوصول إلى منفذ الإعداد، فاستخدم `VPSSRV_SETUP_PUBLIC=0` مع نفق SSH محلي، أو اختر منفذًا مسموحًا بواسطة `VPSSRV_SETUP_PORT`.

على مضيف ثُبّت فيه FRPC، افتح بطاقة **FRPS** أو **FRPC** من الصفحة الرئيسية.
**تعديل FRPS** يغيّر منفذ الربط والرمز؛ ويُبقي الحقل الفارغ قيمته الحالية. يتطلب تغييرهما تحديث مثيلات FRPC المتصلة بخادم FRPS هذا. لكل بطاقة FRPC محلية أزرار مستقلة لاختبار الاتصال والتحرير والحذف بعد تأكيد، ولا يؤدي النقر على خلفيتها أي إجراء. يقع مفتاح تشغيل المثيل بجانب اسمه. افتح التحرير لتغيير اسم المثيل أو الخادم أو تعيينات الوكيل في موضعها. انقر عنوان IP أو المنفذ أو الرمز المخفي لإظهاره؛ ويحمّل فتح تحرير الخادم القيم المحفوظة. يُجري اختبار الاتصال تسجيل دخول مؤقتًا بالقيم المحفوظة، دون تشغيل المثيل المُدار أو تغييره. يتحقق الحفظ بواسطة `frpc verify` ويعيد تشغيل المثيل النشط، ثم يعود إلى صفحته. تُفعّل المثيلات الجديدة بعد أول حفظ صالح. يمكن أيضًا تشغيل مثيل موجود أو إيقافه دون حذف إعداده. لا تغيّر تعديلات المثيلات المحلية عملاء الأجهزة الأخرى. لوكيل TCP، اسمح بمنفذه `remotePort` في جدار حماية المضيف النشط ومجموعة أمان السحابة؛ يسجّل المحرر تخصيصات المنافذ على المضيف نفسه، لكنه لا يغيّر قواعد جدار حماية السحابة.

**إعادة تشغيله تُحدّث التثبيت في مكانه.** يكتشف التثبيت الموجود ويعرض الإبقاء على إعداداته، ولا يسأل إلا عن الإعدادات التي لم تكن متاحة في الإصدار المثبّت، مع عرض قيمتها الافتراضية، لذا يُعدّ ضغط Enter إجابة صالحة. تبقى كلمة مرور اللوحة والمنفذ المحفوظ والشهادات وسجل الزوار وبيانات اعتماد عقدة anytls، وكذلك منفذ وبيانات اعتماد كل بروتوكول proxy مثبّت. أجب بـ`n` عن سؤال الترقية لإعادة السؤال عن الإعدادات بدلًا من ذلك.

## إرشادات

### بدء سريع

يضع الإصدار 2.0.0 تنفيذ الويب في `src/web/app.py` ويشغّل المثبّتات من `deploy/`. توجد الملفات التنفيذية المضمّنة وإشعارات تراخيصها تحت `third_party/`، وبيانات الإصدار في `config/`. تبقى الملفات المثبّتة في تخطيط مسطح تحت `$PREFIX`؛ ولا ينقل تغيير تخطيط نسخة المستودع بيانات التشغيل. اجتازت المسارات الجديدة الاختبارات المحلية، لكن هذا الإصدار لم يُقبل بعد على مضيف حقيقي.

```bash
bash deploy/install.sh                       # إعداد تفاعلي عبر معالج مؤقت في المتصفح
sudo VPSSRV_MODULES=web,iperf3 bash deploy/install.sh   # تثبيت آلي دون أسئلة
systemctl status vps-server-web              # هل الخدمة قيد التشغيل
bash deploy/anytls/setup-anytls.sh status           # تفاصيل عقدة anytls، إذا كانت هذه الوحدة مثبّتة
bash deploy/proxy/setup-proxy.sh status             # تفاصيل عقدة proxy، إذا كانت هذه الوحدة مثبّتة
```

ثم من جهاز آخر:

```bash
curl -sS  http://<ip>/                     # التحقق من الوصول عبر HTTP العادي
curl -sSk https://<ip>/                    # ... وعبر TLS أيضًا (بشهادة ذاتية التوقيع)
iperf3 -c <ip> -p 5201 --json              # فقط أثناء فتح نافذة الاختبار
```

### التحقق من عمله

بعد `bash deploy/install.sh`، ينبغي أن ترى كتلة ملخّص تذكر كل وحدة مثبّتة ومنفذها. ثم:

- يُظهر `systemctl status vps-server-web` الحالة `active (running)`.
- يُظهر فتح `http://<ip>/` من **جهاز آخر** صفحة عنوانها "Reachable" تعرض عنوان IP العام الخاص بك. ويُظهر فتح `https://<ip>/` الصفحة نفسها بعد قبول تحذير الشهادة، مع HTTPS في سطر البروتوكول.
- يُظهر تسجيل الدخول إلى `http://<ip>:<console port>/` لوحة التحكم مع عنصر التحكم في iperf3 والنافذة مغلقة.
- بعد فتح نافذة لخمس دقائق، يُظهر `iperf3 -c <ip> -p 5201 --json` من جهاز آخر معدل النقل ويتضمن `mean_rtt`. وبعد خمس دقائق يفشل الأمر نفسه في الاتصال؛ وهذا إغلاق النافذة تلقائيًا، وليس عطلًا.
- إذا ثبّتَّ anytls: يُظهر `systemctl status vps-server-anytls` الحالة `active (running)`.
- إذا ثبّتَّ proxy: يُظهر `systemctl status vps-server-proxy` الحالة `active (running)`.

### الإعداد

لكل متغير قيمة افتراضية صالحة؛ وملف `.env` اختياري. أهم المتغيرات:

| المتغير | المعنى | القيمة الافتراضية | مطلوب |
|---|---|---|---|
| `VPSSRV_PUBLIC_HTTP_PORT` | صفحة التحقق العامة، بنص واضح | `80` | لا |
| `VPSSRV_PUBLIC_HTTPS_PORT` | صفحة التحقق العامة، عبر TLS | `443` | لا |
| `VPSSRV_PUBLIC_ENABLE` | تفعيل الصفحة العامة | `1` | لا |
| `VPSSRV_CONSOLE_PORT` | منفذ اللوحة؛ القيمة `0` تولّد منفذًا وتحفظه | `0` | لا |
| `VPSSRV_AUTH` | اشتراط كلمة مرور للوحة | `1` | لا |
| `VPSSRV_IPERF_PORT` | المنفذ الذي تستمع عليه نافذة iperf3 المفتوحة | `5201` | لا |
| `VPSSRV_IPERF_MAX_MINUTES` | الحد الأقصى الذي لا يمكن تجاوزه من اللوحة | `60` | لا |
| `VPSSRV_DEFAULT_LANG` | `en` / `zh_cn` / `zh_tw` / `zh_hk` / `hi` / `es` / `ar` / `fr` | `en` | لا |

المرجع الكامل: [مرجع الإعدادات][local-link-002].

## الترقية

للترقية، استخدم نسخة عمل حديثة وأعد تشغيل المثبّت بالدليل نفسه وخيارات الوحدات نفسها. احتفظ بنسخة احتياطية من البيانات الدائمة حتى تتحقق من الخدمات واللوحة بعد الترقية.

## إلغاء التثبيت

شغّل الأمر بصلاحيات root من نسخة المثبّت، باستخدام قيمتي `PREFIX` و`SERVICE_NAME` نفسيهما المستخدمتين عند التثبيت (يطبع ملخّص المثبّت أمر الإزالة الدقيق). لإزالة الوحدات والخدمات المثبّتة **مع
الاحتفاظ بالبيانات** داخل `$PREFIX` لإعادة تثبيت لاحقة:

```bash
KEEP_DATA=1 bash deploy/uninstall.sh
```

لإزالة الوحدات المثبّتة **وحذف البيانات أيضًا** (بما في ذلك سجل الزوار وكلمة مرور اللوحة والمنفذ المحفوظ والشهادات داخل `$PREFIX`):

```bash
bash deploy/uninstall.sh
```

يفكّ كلا الوضعين خدمات anytls/proxy وإعدادات وحداتهما المنفصلة إذا كانت مثبّتة. يحتفظ `KEEP_DATA=1` بـ`$PREFIX`، لا بإعدادات تلك الوحدات.
