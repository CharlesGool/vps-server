## परिचय

Debian/Ubuntu VPS के लिए मॉड्यूल चुनकर स्थापित किया जाने वाला पैकेज: वेब पोर्ट की पहुँच जाँचने के लिए सार्वजनिक पृष्ठ, गति परीक्षण और कनेक्शन लॉग के लिए संचालक कंसोल, आवश्यकता पर चालू होने वाला iperf3 परीक्षण समय, और sing-box प्रॉक्सी नोड। संस्करण 2.0.0 में चार-प्रोटोकॉल वाला `proxy` मॉड्यूल और frps तथा Lucky के प्रयोगात्मक इंस्टॉलर भी शामिल हैं। [वर्तमान स्थिति और स्वीकृति की सीमाएँ][local-link-001] देखें।

## यह क्या करता है

- **किसी भी व्यक्ति को पहुँच की पुष्टि देता है।** पोर्ट **80** और
  **443** पर जानबूझकर अत्यंत साधारण पृष्ठ, बिना लॉगिन के। किसी को IP दें; अगर पृष्ठ दिखाई दे, तो उसके स्थान से आपके वेब पोर्ट उपलब्ध हैं। पृष्ठ उसका स्रोत IP, सर्वर का समय तथा इस्तेमाल हुआ पोर्ट और प्रोटोकॉल बताता है — होस्ट के बारे में और कुछ नहीं।
- **ब्राउज़र से थ्रूपुट मापता है।** स्थायी रूप से सहेजे गए यादृच्छिक ऊँचे पोर्ट पर पासवर्ड-सुरक्षित कंसोल LibreSpeed इंजन से अपलोड/डाउनलोड परीक्षण करता है।
- **माँग पर iperf3 से थ्रूपुट और विलंब मापता है।** कंसोल सीमित अवधि की परीक्षण खिड़की खोलता है; `iperf3 -s` केवल उसी दौरान चलता है और अवधि समाप्त होने पर बंद हो जाता है। परीक्षक को iperf3 से बैंडविड्थ मिलती है और Linux क्लाइंट पर `mean_rtt` से राउंड-ट्रिप समय, जो उसके `--json` आउटपुट में होता है भी मिलता है। यह मान कर्नेल के `TCP_INFO` से आता है और उन क्लाइंट में नहीं होता जो इसे पढ़ नहीं सकते, विशेषकर Windows पर Cygwin के अंतर्गत iperf3। UDP मोड (`-u`) हर प्लेटफ़ॉर्म पर जिटर और पैकेट हानि बताता है।
- **कनेक्ट होने वालों का लॉग रखता है।** केवल HTTP नहीं, किसी भी पोर्ट पर आने वाला हर TCP कनेक्शन `/proc/net/tcp[6]` से पढ़ा जाता है और SQLite में रखा जाता है; सबसे हाल के 1000 रिकॉर्ड सुरक्षित रहते हैं।
- **anytls प्रॉक्सी देता है।** स्वयं हस्ताक्षरित प्रमाणपत्र और BBR सहित sing-box। मॉड्यूल स्थापित होने पर कंसोल का `/proxy` पृष्ठ नोड की स्थिति दिखाता है और उसका Clash प्रविष्टि तथा कॉपी बटन वाला `anytls://` लिंक देता है, ताकि क्लाइंट को नोड देने के लिए फिर टर्मिनल पर न जाना पड़े।
- **vmess/vless/trojan/shadowsocks प्रॉक्सी, इनमें से कोई भी संयोजन देता है।** एक अतिरिक्त sing-box प्रक्रिया anytls वाला ही साथ वितरित बाइनरी इस्तेमाल करती है। स्थापित होने पर साझा `/proxy` पृष्ठ पर हर प्रोटोकॉल के लिए पोर्ट, UUID या पासवर्ड, Clash प्रविष्टि, शेयर लिंक और QR कोड वाला अलग अनुभाग आता है। हर प्रोटोकॉल का अपना रीसेट बटन है, जो अन्य क्रेडेंशियल नहीं बदलता।

चुनने योग्य मॉड्यूल web, iperf3, anytls, proxy, frps और Lucky हैं। frps और Lucky प्रयोगात्मक हैं; इस संस्करण के लिए वास्तविक होस्ट पर इनके व्यवहार की स्वीकृति नहीं हुई है।

**दायरे से बाहर:** ACME या डोमेन नाम नहीं (443 पर जानबूझकर स्वयं हस्ताक्षरित प्रमाणपत्र है); लगातार चलने वाला iperf3 नहीं; रिवर्स प्रॉक्सी या कंटेनर नहीं; सार्वजनिक पृष्ठ होस्टनाम, कर्नेल, अपटाइम, सेवाओं की सूची या प्रॉक्सी पैरामीटर कभी नहीं बताता। यह परियोजना `vps-webserver` या `Anytsl-Serve` की जगह नहीं लेती — दोनों का रखरखाव स्वतंत्र रूप से जारी है और उनके कोड को समाहित करने के बजाय यहाँ विक्रेता-कोड के रूप में रखा गया है।

## आवश्यकताएँ

- OS: Debian 11+ या Ubuntu 20.04+, systemd, root के रूप में चलाएँ
- रनटाइम: Python 3.9+ (वितरण का `python3` पर्याप्त है — स्थापित करने के लिए कोई Python निर्भरता नहीं)
- आर्किटेक्चर: web और iperf3 के लिए कोई भी; anytls, proxy, frps और Lucky के लिए **केवल x86-64**, क्योंकि साथ वितरित एक्ज़ीक्यूटेबल amd64 के लिए हैं।
- web मॉड्यूल के डिफ़ॉल्ट सार्वजनिक पोर्ट के लिए 80 और 443 **अनिवार्य रूप से** खाली होने चाहिए — इंस्टॉलर nginx, Apache, Caddy या `vps-webserver` से टकराने के बजाय स्थापना रोकता है
- बाहरी सेवाएँ: रनटाइम पर कोई नहीं। स्थापना के लिए आपके वितरण का पैकेज मिरर चाहिए; वैकल्पिक सार्वजनिक-IP खोज बाहरी सेवा से संपर्क कर सकती है।
- न्यूनतम: ऊपर दिया OS, रनटाइम, आर्किटेक्चर और खाली पोर्ट। अतिरिक्त अनुशंसित हार्डवेयर आवश्यकता दर्ज नहीं है; लगभग 150 MB डिस्क वाला VPS साथ वितरित बाइनरी रख सकता है।

## इंस्टॉल करना

एक-पंक्ति त्वरित स्थापना (नवीनतम रिलीज़ टैग, कोई कॉन्फ़िगरेशन वेरिएबल नहीं):

```bash
git clone --branch v2.0.0 --depth 1 https://github.com/CharlesGool/vps-server.git vps-server && cd vps-server && bash deploy/install.sh
```

कॉन्फ़िगरेशन सहित चरणबद्ध तरीका:

```bash
# Always clone a tag, not the default branch — the branch tip may be mid-work.
# Latest release tag: git ls-remote --tags https://github.com/CharlesGool/vps-server.git
git clone --branch v2.0.0 --depth 1 https://github.com/CharlesGool/vps-server.git vps-server
cd vps-server
cp .env.example .env   # optional — every variable has a working default
bash deploy/install.sh
```

`deploy/install.sh` पूछता है कि कौन से मॉड्यूल लगाने हैं, इंटरफ़ेस की भाषा क्या होगी, कंसोल पासवर्ड-सुरक्षित रखना है या नहीं, और कौन से पोर्ट इस्तेमाल होंगे। v2.0.0 टैग में चुनने योग्य सभी छह मॉड्यूल हैं; frps और Lucky प्रयोगात्मक हैं।

**दोबारा चलाने पर उसी स्थापना का उन्नयन होता है।** यह मौजूदा स्थापना पहचानता है, उसका कॉन्फ़िगरेशन रखने का विकल्प देता है और केवल उन सेटिंग के बारे में पूछता है जो स्थापित संस्करण में नहीं थीं — हर एक का डिफ़ॉल्ट दिया जाता है, इसलिए Enter दबाना मान्य उत्तर है। कंसोल पासवर्ड, सहेजा गया पोर्ट, प्रमाणपत्र, विज़िटर लॉग, anytls नोड के क्रेडेंशियल और हर स्थापित प्रॉक्सी प्रोटोकॉल का पोर्ट व क्रेडेंशियल सुरक्षित रहते हैं। इसके बजाय सेटिंग दोबारा पूछने के लिए उन्नयन प्रश्न पर `n` चुनें।

## मार्गदर्शन

### तुरंत शुरू करें

संस्करण 2.0.0 में वेब कार्यान्वयन `src/web/app.py` में है और इंस्टॉलर `deploy/` से चलते हैं। साथ वितरित बाइनरी और लाइसेंस सूचनाएँ `third_party/` में तथा रिलीज़ मेटाडेटा `config/` में है। स्थापित फ़ाइलें `$PREFIX` के अंतर्गत समतल लेआउट में रहती हैं; चेकआउट का लेआउट बदलने से रनटाइम डेटा स्थानांतरित नहीं होता। नए पथों पर स्थानीय परीक्षण सफल हुए हैं, लेकिन इस संस्करण को वास्तविक होस्ट पर अभी स्वीकृति नहीं मिली है।

```bash
bash deploy/install.sh                       # interactive: temporary browser setup wizard
sudo VPSSRV_MODULES=web,iperf3 bash deploy/install.sh   # unattended, no prompts
systemctl status vps-server-web              # is it up
bash deploy/anytls/setup-anytls.sh status           # anytls node details, if that module is installed
bash deploy/proxy/setup-proxy.sh status             # proxy node details, if that module is installed
```

फिर दूसरी मशीन से:

```bash
curl -sS  http://<ip>/                     # reachability over plain HTTP
curl -sSk https://<ip>/                    # ... and over TLS (self-signed)
iperf3 -c <ip> -p 5201 --json              # only while a window is open
```

### काम करने की पुष्टि करें

`bash deploy/install.sh` के बाद स्थापित हर मॉड्यूल और उसका पोर्ट बताने वाला सारांश दिखाई देना चाहिए। फिर:

- `systemctl status vps-server-web` में `active (running)` आता है।
- **दूसरी मशीन** से `http://<ip>/` खोलने पर "Reachable" शीर्षक वाला पृष्ठ आपका सार्वजनिक IP दिखाता है। प्रमाणपत्र चेतावनी स्वीकार कर `https://<ip>/` खोलने पर वही पृष्ठ दिखता है और प्रोटोकॉल पंक्ति में HTTPS होता है।
- `http://<ip>:<console port>/` पर लॉगिन करने पर डैशबोर्ड में iperf3 नियंत्रण दिखता है और परीक्षण खिड़की बंद होती है।
- पाँच मिनट की खिड़की खोलने के बाद दूसरी मशीन से `iperf3 -c <ip> -p 5201 --json` चलाने पर थ्रूपुट मान और `mean_rtt` मिलता है। पाँच मिनट बाद वही कमांड कनेक्ट नहीं हो पाती — यह खिड़की का अपने आप बंद होना है, खराबी नहीं।
- anytls स्थापित किया हो तो `systemctl status vps-server-anytls` में `active (running)` आता है।
- proxy स्थापित किया हो तो `systemctl status vps-server-proxy` में `active (running)` आता है।

### कॉन्फ़िगरेशन

हर वेरिएबल का उपयोगी डिफ़ॉल्ट है; `.env` वैकल्पिक है। मुख्य वेरिएबल:

| वेरिएबल | अर्थ | डिफ़ॉल्ट | अनिवार्य |
|---|---|---|---|
| `VPSSRV_PUBLIC_HTTP_PORT` | सार्वजनिक पहुँच पृष्ठ, बिना TLS | `80` | नहीं |
| `VPSSRV_PUBLIC_HTTPS_PORT` | सार्वजनिक पहुँच पृष्ठ, TLS सहित | `443` | नहीं |
| `VPSSRV_PUBLIC_ENABLE` | सार्वजनिक पृष्ठ चालू रखना | `1` | नहीं |
| `VPSSRV_CONSOLE_PORT` | कंसोल पोर्ट; `0` एक पोर्ट बनाकर सहेजता है | `0` | नहीं |
| `VPSSRV_AUTH` | कंसोल पर पासवर्ड आवश्यक | `1` | नहीं |
| `VPSSRV_IPERF_PORT` | खुली iperf3 खिड़की का पोर्ट | `5201` | नहीं |
| `VPSSRV_IPERF_MAX_MINUTES` | कंसोल की अधिकतम अवधि | `60` | नहीं |
| `VPSSRV_DEFAULT_LANG` | `en` / `zh_cn` / `zh_tw` / `zh_hk` / `hi` / `es` / `ar` / `fr` | `en` | नहीं |

पूरी सूची: [कॉन्फ़िगरेशन संदर्भ][local-link-002]।

## अनइंस्टॉल करना

इंस्टॉलर चेकआउट से root के रूप में चलाएँ, और स्थापना के समय वाले ही `PREFIX` और `SERVICE_NAME` मान दें (इंस्टॉलर का सारांश हटाने की सटीक कमांड छापता है)। स्थापित मॉड्यूल और यूनिट हटाते हुए भविष्य की पुनर्स्थापना के लिए `$PREFIX` में **डेटा
सुरक्षित रखने** हेतु:

```bash
KEEP_DATA=1 bash deploy/uninstall.sh
```

स्थापित मॉड्यूल के साथ `$PREFIX` का **डेटा भी मिटाने** के लिए (विज़िटर लॉग, कंसोल पासवर्ड, सहेजा पोर्ट और प्रमाणपत्र सहित):

```bash
bash deploy/uninstall.sh
```

दोनों तरीके स्थापित होने पर anytls/proxy सेवाएँ और उनके अलग मॉड्यूल कॉन्फ़िगरेशन हटा देते हैं। `KEEP_DATA=1` केवल `$PREFIX` सुरक्षित रखता है, उन मॉड्यूल कॉन्फ़िगरेशन को नहीं।

## आभार

ब्राउज़र परीक्षण [LibreSpeed](https://github.com/librespeed/speedtest) इस्तेमाल करता है; QR रेंडरिंग
[qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) इस्तेमाल करती है; साथ वितरित प्रॉक्सी कोर
[sing-box](https://github.com/SagerNet/sing-box) है। प्रयोगात्मक मॉड्यूल में
[frp](https://github.com/fatedier/frp) और
[Lucky](https://github.com/gdy666/lucky) भी साथ वितरित हैं। घटकों की सूची और मूल लाइसेंस के पथ [तृतीय-पक्ष सूचनाओं][local-link-003] में हैं।
