## 限制

- 已删除且没有备份的旧状态目录无法恢复, 因为原始数据已不存在.
- 仅凭本机网卡不能可靠推断 NAT 后的公网地址;本项目不查询外部公网 IP 服务.
- 任意复杂 FRP 配置不能由现有结构化编辑器无损重建;未支持字段需保留并通过原生配置管理.

## 交接

当前分支: `main`, 与 `origin/main` 同步. 当前正式版本: v5.3.1(标签 `v5.3.1`, GitHub Release 含完整安装包与 `SHA256SUMS`). 上一个测试预发布为 `v5.3.1-test.1`.

已完成: v5.3.1 的模块安装, 卸载与重装修复(见 `doc/CHANGELOG.md`), 测试预发布 `v5.3.1-test.1` 经操作员测试, 未发现明显问题. 此前已完成 v5.3.0 发布内容, 变更见 `doc/CHANGELOG.md`: 共享 Web UI(顶栏与底栏逐项重排动画, 设置侧栏缓动跟随, 标签页图标随主题, 跟随系统外观, 刷新不闪旧布局), 控制台对话框, Clash 二维码按钮, 公网页纯文本, 各功能页面排版, Tailscale 连接互斥, iperf3 状态竞争与安装器端口误判修复. 顶栏左上角只显示项目名称是项目特例, 见上方决策.

检查结果: `check_project.py` 与 `web/` 的 `npm run check` 通过. v5.3.1 的测试预发布未在新增机器上做专项验收, 只经操作员测试. 测试预发布 `v5.3.0-test.1` 在一台 Debian 13 x86-64 测试机和一台真机从 v5.2.x 原地升级, 两处表现一致, 真机 Tailscale 工作正常(操作员确认).

未验证: 整机重启后的自启动; Python 3.9 与其他发行版; 真实移动设备; 已登录 Tailscale 退出及真实 Tailnet 路由策略的专项验证; 连接 Tailscale 的互斥只在代码层面和单次点击上验证. 测试机上安装器输出写"公开页已关闭", 但状态目录 `web-http-enabled` 为 1, 80 和 443 仍在监听, 与端口登记表一致, 未判断提示是否需要调整. 端口登记助手曾在 2026-10-06 日志中排队 90 多秒, 原因未查明.

剩余步骤: `tokens.css` 中的 `compat-*` 数字标记缺少语义名称, 可按用途逐步改名. 英语/西班牙语文档尚无母语审阅. 下一步: 按实际部署环境选择专项验收.
