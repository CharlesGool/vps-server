### v5.0.0 — 2026-10-03

#### 新增

- 主控台可向另一台 iperf3 伺服器發起有時限的 TCP 或 UDP 測試,並提供簡短的伺服器端及用戶端指令.
- 公開 HTTP 與 HTTPS 頁面有獨立開關和首頁入口;伺服器標識可持續儲存並顯示於導覽及瀏覽器標題.

#### 變更

- 首次安裝直接在終端完成,預設只安裝 Web 主控台;模組頁面可按需要安裝其他功能.FRPC 啟用狀態獨立於用戶端執行個體的執行狀態.
- Web 功能處理器與樣式按功能拆分,靜態資源歸入 `src/web/static/`;專案文件依簡體中文來源,歷史記錄,變更紀錄及翻譯檔案整理.
- 一般 Web 服務重新啟動會保留未過期的登入工作階段;修改密碼仍會使舊工作階段失效.

#### 修復

- FRPC 執行個體名稱支援 Unicode 字母與數字;重新安裝模組會保留已安裝節點與服務狀態,並可在重新啟動前回報開關結果.
- 完整解除安裝在刪除安裝目錄後,仍能列印在地化結束訊息並以成功狀態結束.

### v4.0.0 — 2026-09-29

#### 新增

- 透過帶一次性密碼的臨時 HTTPS 監聽器,在瀏覽器中完成首次設定,選擇模組,語言,認證方式和埠.安裝後的控制檯可在 Settings 安裝或移除可選模組,並顯示任務狀態和日誌.
- 可建立,重新命名,編輯,啟用,停用,測試及刪除本機 FRPC 例項.編輯器支援簡單的令牌認證 TCP/UDP 代理,用 `frpc` 驗證修改,應用失敗時恢復舊配置.FRPC 可獨立於 FRPS 安裝;其帶固定校驗和的客戶端二進位制檔案作為 `frpc-0.71.0-linux-amd64` Release 資源分發.
- Home 分別提供 FRPS 和 FRPC 入口及頁面.已停用功能的頁面會轉到本地化的“頁面已關閉”頁面.

#### 變更

- Home 將九項主要功能顯示為帶獨立開關的卡片.模組管理移至普通 Settings;Security Settings 仍受最近一次管理員密碼驗證保護.
- FRPC 和代理節點卡片的編輯,測試,顯示及確認控制元件更加清楚.編輯例項時,未修改的伺服器地址和令牌保持原值;代理欄位區分本地埠與伺服器埠.
- 登入頁與 Settings 導航,頁面圖示,密碼控制元件,主題選項及響應式佈局遵循當前控制檯設計.正文使用系統字型,以維持重新整理時的文字尺寸.根據操作員反饋移除頁面切換動畫;調整視窗大小時的動效仍保留.
- 埠轉發開關由執行中的 Web 程序協調規則,無需重啟控制檯.重複提交模組操作會返回頁面;被拒絕的 POST 請求會正確關閉連線,避免把後續請求誤解析.

#### 修復

- 新增 FRPC 代理不再要求僅用於編輯或刪除代理的索引.功能停用時停止訪客採集;重新開啟代理節點控制元件時保留已儲存的值.

#### 驗證和限制

- 本地測試透過 341 項,跳過 8 項.指定測試機檢查了已登入路徑,FRPS/FRPC 頁面分離,模組開關,關閉頁面跳轉,FRPC 配置驗證,以及使用者要求的指定遠端埠 TCP 代理.操作員認為當前重新整理效果可以接受.測試機目前仍執行已打補丁的測試版本;釋出此正式原始碼標籤本身不會升級該安裝.
- 真實移動裝置,重啟後的永續性,從最終標籤在全新主機完整安裝,以及所有真實代理或轉發策略組合尚未驗證.此前釋出的三個大型可執行檔案與 v3.0.0 相同.FRPC 客戶端是新增的 16,593,080 位元組 Release 資源,SHA-256 為 `f79fff8de3089ec711ff8bdd4b73e00dfe491a1c3d754983c8b0f8d58c21b068`;安裝程式在使用前驗證該摘要.

### v3.0.0 — 2026-09-28

#### 新增

- 可以單獨建立,編輯,停用,重置和刪除託管 AnyTLS,VMess,VLESS,Trojan 和 Shadowsocks 節點.顯示數字保持連續;隱藏的 UUID 保留身分.連接詳細資訊可以透過連結或二維碼複製或匯入到 Android 版 Clash Meta.
- 每個節點都會追蹤上傳和下載流量,並支援 GiB 上限,單獨的定向速度限制,按天,月或年重複重置以及可選的有效期.達到上限可以將兩個方向的速率限制為 1 Mbps 或阻止存取;過期的有效期會阻止存取.
- 明確的私有 IP 允許清單可以使用無密碼存取.在公開或更改憑證和存取規則之前,安全性設定需要最近檢查管理員密碼,包括僅限 IP 的會話.

#### 變更

- 統一控制台和登入佈局,響應式節點卡,儀表板導航和設定.普通設定現在提供八種持久的強調色和獨立的明/暗模式.儲存的憑證和配置的連接埠將被屏蔽,直到授權顯示或使用為止.
- iperf3 視圖將服務狀態與其可編輯連接埠分開.安裝程式升級保留執行階段 Web 入口點和暫存模組.代理設定摘要列出介面和可選的 Tailscale 位址,無需公共 IP 查找.修復了翻譯的文檔片段和第三方來源連結.

#### 驗證與限制

- 操作員報告功能測試已通過.本機套件通過了 311 項測試(跳過了 8 項);指定的測試主機為新的登入和主題資產提供服務,其中 Web,代理,節點流量計量服務和 AnyTLS 服務處於活動狀態並啟用啟動.在此版本準備過程中,並未獨立見證實際的重新啟動和每個即時策略傳輸.
- 未新增超過 10 MB 的新的或變更的 blob. 現有的 sing-box(57,995,520 位元組),frps(20,332,728 位元組)和 Lucky(10,883,644 位元組)可執行檔案具有與 `v2.0.0` 中相同的 Git blob ID; 出處和許可證記錄保留在 [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md) 中. frps 和 Lucky 仍處於試驗階段.

### v1.1.0 — 2026-09-19

<a id="vps-release-v1-1-0"></a>

#### 新增

- **主控台管理的連接埠轉送.**新的"連接埠轉送"頁面可將本機的公開 TCP/UDP 連接埠轉送到經 Tailscale 或區域網路可達的裝置 — 適用於本機有公開 IP,目標裝置沒有的情況.可在主控台新增,啟用,停用和刪除規則;套用每條規則前,會檢查與本次安裝已使用的每個連接埠(主控台,公開頁面,iperf3,anytls)有無衝突.規則透過 `iptables` DNAT + MASQUERADE 實作,每次服務啟動自動重新套用,因此服務重啟或主機重新開機後會立即恢復所有已啟用的轉送,不會遺失.首次需要時會自動開啟 `net.ipv4.ip_forward`.設定 `VPSSRV_PORTFWD_ENABLE=0` 可從安裝中完全移除此功能.

### v1.0.3 — 2026-09-12

#### 修復

### v1.0.0 — 2026-09-12

首個發行版.結合兩個既有專案 — 密碼保護的 VPS 測速主控台及 sing-box `anytls` 安裝程式 — 並新增兩者原本都沒有的兩項功能:按需開啟的 iperf3 時段,以及讓任何人檢查你的 IP 是否能透過網頁連通的公開頁面.

#### 新增

- **連接埠 80 和 443 上無須登入的公開可達性頁面.**將 IP 給對方;如果頁面能顯示,就表示從對方所在位置可連上你的網頁連接埠.頁面顯示對方的來源位址,伺服器時鐘,以及連入的連接埠和協定 — 不揭露其他主機資訊.刻意同時提供兩個連接埠,以區分"主機無法連線"與"只有 443 遭封鎖".
- **按需開啟的 iperf3 時段.**主控台可開啟限時時段;`iperf3` 僅於時段內執行,在目前使用的防火牆開啟其連接埠,時段到期,依要求關閉或服務停止時會關閉服務及連接埠.沒有"保持執行"選項,因公開的 iperf3 伺服器可讓任何陌生人占滿上行頻寬.時段開啟時公開頁面會顯示此資訊,讓測試者知道何時連線.
- **瀏覽器測速及訪客記錄**,均從主控台使用:透過 LibreSpeed 引擎測量上傳/下載速度,並從核心連線表讀取任何連接埠(不只 HTTP)的每筆傳入 TCP 連線.
- **anytls 代理模組.**使用自簽憑證的 sing-box,加上 BBR.主控台顯示節點連接埠,密碼及 SNI,提供可複製的 Clash 項目及 `anytls://` 連結,並可輪替憑證.
- **可選擇模組的安裝程式.**web,iperf3 和 anytls 可透過互動方式或無人值守的 `VPSSRV_MODULES` 分別選取.若其他行程占用連接埠,會拒絕而非爭用;在非 x86-64 架構略過 anytls,而非安裝無法執行的執行檔.
- **可感知升級的重新安裝.**重新執行安裝程式時,會偵測既有安裝,提供保留設定的選項,重播服務單元記錄的設定,保留 anytls 節點憑證,且僅詢問已安裝版本沒有的設定.早於上述記錄機制的安裝則從磁碟讀取模組清單.
- **三種介面語言** — 英文,簡體中文,繁體中文 — 安裝時選取,每次造訪可切換,並會記住選擇.
- **離線安裝.**sing-box 執行檔隨儲存庫提供,因此安裝只需連上發行版的套件鏡像站.

**發行說明(v1.0.0):**

- 整個專案採 GPL-3.0,因為重新散布 GPL-3.0 的 sing-box 執行檔.元件授權及 GPL 要求的對應原始碼連結,列於 [THIRD_PARTY_NOTICES.md][local-link-007].
- 443 上的 TLS 使用自簽憑證:沒有網域或 ACME.瀏覽器警告仍可證明該連接埠有回應,這正是該頁面要解答的問題.
- iperf3 JSON 輸出的 `mean_rtt` 來自核心的 `TCP_INFO`,因此 Linux 用戶端會回報往返時間;無法讀取此資訊的用戶端(例如 Windows 上透過 Cygwin 執行的 iperf3)只會回報吞吐量.UDP 模式(`-u`)則在所有平台上提供抖動及遺失率.
- anytls 模組僅支援 x86-64;web 和 iperf3 模組不受架構限制.
