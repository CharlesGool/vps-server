## 決策

<a id="vps-decisions"></a>

以下依日期記錄的決策,保留了被否決的替代方案及其代價.歷史決策不構成新的法律或發行核准.

| 決策 | 理由,否決的替代方案及代價 |
| --- | --- |
| 2026-09-22 — `proxy` 使用單一 sing-box 行程,最多四個 inbounds,而非複製四份 anytls | - **已解決,並非否決:**內附的 sing-box 執行檔是否支援 vmess/vless/trojan/shadowsocks — 已實際在同一行程中同時執行四種協定確認(不只執行 `sing-box check`),無須第二套後端.曾測試 hysteria2/tuic,但因欄位/TLS 要求不同而未納入. - **否決:**每種協定各用一個 systemd 單元及設定檔,完全仿照 anytls 本身的配置 — 需監控四個單元,會有三張多餘的自簽憑證,且不符合未來按節點統計流量的功能所需的配置形式(一個行程,其 `inbounds` 清單本身就是節點清單). - **代價:**兩個獨立模組現在共用內附執行檔;各模組的 `uninstall()` 刪除執行檔前都**必須**檢查另一個模組的設定是否存在(anytls 內附指令碼因此新增有記錄的本地修改 — 見 `anytls/.upstream-version`). |
| 2026-09-21 — `prompt_new_settings()` 明確以 `return 0` 結束,而非直接走出迴圈 | - **否決:**讓函式結束狀態取決於最後的 `for` 迴圈,就像 `install.sh` 中大多數函式一樣 — 該迴圈原本最後一句是單獨的 `[ -n "$value" ] && export ...`,若最後一項提示設定維持預設值,測試便為 false,並成為函式的傳回狀態.直接呼叫此函式時(`prompt_new_settings` 位於 `if` 主體內,但本身不豁免 `set -e`),會在最後提示後悄悄中止整個安裝程式 — 無錯誤,未複製檔案,未寫入 `VERSION`,未重新啟動服務.已在 v1.0.4 → v1.1.1 的實機升級重現;修復方式為以 `if`/`fi` 包住 export,並明確在結尾加上 `return 0`,讓函式結束狀態不再取決於最後提示的設定. - **不要將結尾的 `return 0` 當成無用程式碼移除.**它是修復,不是樣板程式碼. |
| 2026-09-19 — 連接埠轉送採用 iptables DNAT,每次啟動從 JSON 重新套用;不在行程外寫入規則 | - **否決:**每條規則使用 `socat` 使用者空間轉送 — 較安全(不修改 NAT 表或 `ip_forward`),但使用者明確選擇此專案採用核心層級的 DNAT+MASQUERADE. - **否決:**透過 `iptables-persistent` 讓規則在重新開機後留存於核心層級 — 這會讓主控台與系統套件成為同一組規則的兩個事實來源.`app.py` 改為每次啟動時從自己的 JSON 重套規則(DESIGN.md 的"連接埠轉送生命週期"),因此只有一個事實來源. - **否決:**移除最後一條轉送後自動將 `net.ipv4.ip_forward` 還原為 `0` — 這是整台主機的設定,其他軟體(此專案自己的測試主機有執行 Docker)可能需要它維持開啟. - **代價:**停止 `vps-server-web`(不是重新啟動)會撤銷所有轉送的核心狀態,包括已啟用規則 — 與 iperf3 時段一樣採取失效安全方向.不要為了"修復"此行為把規則移至獨立的常駐單元;此方案已考慮並在上文否決. |
| 2026-09-12 — 公開頁面與主控台使用不同的監聽器和處理器類別 | - **否決:**由同一監聽器提供兩者,以路徑前綴及身分驗證檢查保護主控台路由 — 身分驗證檢查可能因程式錯誤而放行;不存在的路由則不會. - **否決:**將主控台本身置於 80/443,以密碼保護並捨棄隨機連接埠 — 這會失去 `vps-webserver` 刻意選擇的隱蔽層. - **代價:**一個行程有三個監聽器,兩個處理器類別均須分別接上訪客記錄掛鉤. - **不要再把此方案當成改善項目加入.** |
| 2026-09-12 — iperf3 僅在操作者開啟的限時時段內執行 | - **否決:**一直開放公開的 `iperf3 -s` — 任何陌生人都可以無限期占滿上行頻寬,且不會顯示此情況正在發生. - **否決:**常駐執行並使用 `--authorized-users-path` RSA 驗證 — 測試前就得透過其他管道交付憑證,違背"給對方 IP 就能測量"的目的. - **代價:**遠端測試者無法在無人值守時測試;得先有人開啟時段.公開頁面會顯示已開啟的時段,讓測試者知道何時連線. |
| 2026-09-12 — 連接埠 443 使用自簽憑證;沒有 ACME,也不需要網域 | - **否決:**對真實網域使用 certbot / acme.sh — 頁面的目的是回答"能否連到這個 IP",瀏覽器警告頁面本身就證明可達.為此加入網域依賴及續期計時器毫無助益. - **否決:**只在連接埠 80 提供服務 — 無法區分"主機無法連線"與"只有 443 遭封鎖",而後者是值得偵測的常見情況. - **代價:**每次透過 HTTPS 存取都會看到憑證警告.這是預期行為;不要用 HSTS 或固定的例外設定"修復". |
| 2026-09-12 — sing-box 執行檔隨儲存庫提供,因此整個專案採用 GPL-3.0 | - **否決:**安裝時下載 sing-box 以縮小儲存庫並維持 Apache-2.0 授權 — `Anytsl-Serve` 早已為了確保無法存取 GitHub 時仍可安裝而否決此方案;在此重做決策會暗中推翻該目標. - **否決:**為保留 `vps-webserver` 的 Apache-2.0 而捨棄 anytls 模組 — 需求是結合兩個專案,而非擇一. - **代價:**git 中約 57 MB,且每次更新 sing-box 都會增加;`vps-webserver` 的 Apache-2.0 程式碼在此以 GPL-3.0 重新散布. |
| 2026-09-12 — 上游專案以內附方式引入,而非取代它們或使用 submodule | - **否決:**讓 vps-server 取代 `vps-webserver` 和 `Anytsl-Serve` 並封存兩者 — 三個專案都應維持獨立維護和發行. - **否決:**以 git submodule 指向兩個上游儲存庫 — submodule 無法承載本專案所需的重新命名(單元名稱,執行檔名稱,`VPSWS_` → `VPSSRV_`),而複製儲存庫後還須連線另外兩個儲存庫. - **代價:**相同程式碼分布在三個儲存庫,將逐漸產生差異.緩解方式:`.upstream-version` 檔案記錄每份內附程式碼來自的確切上游標籤,更新內附程式碼時**必須**在同一次提交更新該檔. |

### 分支記錄(2026-09-22 狀態快照)

<a id="vps-branch-record-2026-09-22"></a>

原狀態記錄指出功能已實作並自行測試,但仍待操作者審查;分支疊加於 `feat/hardening-batch`,使用其獨立的 y/n 模組選擇器.第一次在可拋棄的 Docker 環境驗證時,systemd 無法作為 PID 1 執行,因此以替代實作模擬 `systemctl`;實際測試了 sing-box 設定檢查,iptables 規則,憑證輪替,顧及共用執行檔的解除安裝,以及無人值守安裝和重新執行升級.測試中發現並修復兩個錯誤:無效 `PROXY_PROTOCOLS` 的驗證失敗遭吞掉(導致零個 inbounds),以及產生的連接埠超出 sing-box 的 uint16 上限.當時記錄有 19 個新測試,147/147 通過;這**不**構成代理功能的 systemd 或實機驗證.

之後操作者測試發現 `/anytls` 與 `/proxy` 之間的人為分隔,以及多張頂層卡片在 flex 版面中並排顯示.分支現將所有已安裝節點區塊放在 `/proxy` 的同一張卡片內,將 `/anytls` 重新導向該處,並只使用一個導覽項目.由於代理頁面同時在改寫,位址去重及移除 `get_ip()` 的公開 IP 自動偵測,是從 `main` 重新套用至此分支,而非合併而來;分支審查**必須**核對這些獨立套用的變更.歷史記錄指出,合併 anytls+proxy 的迴歸測試夾具和重新導向測試達到 150/150 通過;其後又從 `main` 重新套用 iperf3 倒數計時/指令範例修復,達到 153/153 通過.

操作者後續要求將代理的合併重設按鈕改為每種協定各一個按鈕.`setup-proxy.sh reset <protocol>` 保留其他協定的憑證和連接埠;不帶參數的 `reset` 仍會輪替所有協定,但只能從終端機操作,不能透過主控台.可拋棄容器的檢查輪替了四種已安裝協定中的一種,保留其餘協定及完整協定集合,並確認未知名稱會被拒絕且不修改設定.歷史記錄指出新增/改寫六個測試,156/156 通過;本文不提出新的測試或發行聲明.

就先前已發行的工作而言,狀態記錄了三容器可拋棄測試環境及 119/119 個單元測試之後,操作者在實機檢查 v1.1.0 連接埠轉送.v1.0.0 之前,記錄了操作者在實機檢查兩個連接埠上的公開頁面,主控台與瀏覽器測試,iperf3 在區域網路上達到 2.8 Gbit/s 且時段關閉後拒絕連線,anytls 安裝/重設/清除,升級保留設定,以及全部三種介面語言.這些是歷史觀察,不是目前分支的驗收.舊快照將 SQLite 鎖量測列為下一項調查,並記錄沒有阻斷問題;流量統計,首次啟動精靈,frps,`gdy666/lucky` 功能及高度可自訂的節點不在其範圍內.它們目前分別列於[錯誤][local-link-001]及[設計目標][local-link-002].

### v1.0.0 — 2026-09-12

首個發行版.結合兩個既有專案 — 密碼保護的 VPS 測速主控台及 sing-box `anytls` 安裝程式 — 並新增兩者原本都沒有的兩項功能:按需開啟的 iperf3 時段,以及讓任何人檢查你的 IP 是否能透過網頁連通的公開頁面.

#### 新增

- **連接埠 80 和 443 上無須登入的公開可達性頁面.**將 IP 給對方;如果頁面能顯示,就表示從對方所在位置可連上你的網頁連接埠.頁面顯示對方的來源位址,伺服器時鐘,以及連入的連接埠和協定 — 不揭露其他主機資訊.刻意同時提供兩個連接埠,以區分"主機無法連線"與"只有 443 遭封鎖".
- **按需開啟的 iperf3 時段.**主控台可開啟限時時段;`iperf3` 僅於時段內執行,在目前使用的防火牆開啟其連接埠,時段到期,依要求關閉或服務停止時會關閉服務及連接埠.沒有"保持執行"選項,因公開的 iperf3 伺服器可讓任何陌生人占滿上行頻寬.時段開啟時公開頁面會顯示此資訊,讓測試者知道何時連線.
- **瀏覽器測速及訪客記錄**,均從主控台使用:透過 LibreSpeed 引擎測量上傳/下載速度,並從核心連線表讀取任何連接埠(不只 HTTP)的每筆傳入 TCP 連線.
- **anytls 代理模組.**使用自簽憑證的 sing-box,加上 BBR.主控台顯示節點連接埠,密碼及 SNI,提供可複製的 Clash 項目及 `anytls://` 連結,並可輪替憑證.
- **可選擇模組的安裝程式.**web,iperf3 和 anytls 可透過互動方式或無人值守的 `VPSSRV_MODULES` 分別選取.若其他行程占用連接埠,會拒絕而非爭用;在非 x86-64 架構略過 anytls,而非安裝無法執行的執行檔.
- **可感知升級的重新安裝.**重新執行安裝程式時,會偵測既有安裝,提供保留設定的選項,重播服務單元記錄的設定,保留 anytls 節點憑證,且僅詢問已安裝版本沒有的設定.早於上述記錄機制的安裝則從磁碟讀取模組清單.
- **三種介面語言** — 英文,簡體中文,繁體中文 — 安裝時選取,每次造訪可切換,並會記住選擇.
- **離線安裝.**sing-box 執行檔隨儲存庫提供,因此安裝只需連上發行版的套件鏡像站.

**發行說明(v1.0.0):**

- 整個專案採 GPL-3.0,因為重新散布 GPL-3.0 的 sing-box 執行檔.元件授權及 GPL 要求的對應原始碼連結,列於 [THIRD_PARTY_NOTICES.md][local-link-007].
- 443 上的 TLS 使用自簽憑證:沒有網域或 ACME.瀏覽器警告仍可證明該連接埠有回應,這正是該頁面要解答的問題.
- iperf3 JSON 輸出的 `mean_rtt` 來自核心的 `TCP_INFO`,因此 Linux 用戶端會回報往返時間;無法讀取此資訊的用戶端(例如 Windows 上透過 Cygwin 執行的 iperf3)只會回報吞吐量.UDP 模式(`-u`)則在所有平台上提供抖動及遺失率.
- anytls 模組僅支援 x86-64;web 和 iperf3 模組不受架構限制.
