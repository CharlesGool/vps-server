## v1.1.1 — 2026-09-20

### Fixed

- README 的 Install 小节里，无论是一行式的快速安装命令还是分步安装命令，克隆时
  用的仍然是 `--branch v1.0.4`——v1.1.0 发布后如果照着这份说明操作，装到的会是
  上一个版本，完全遗漏端口转发功能。

## v1.1.0 — 2026-09-19

### Added

- **由控制台管理的端口转发。** 新增的"Port forward"页面可以把本机上的一个公网
  TCP/UDP 端口，转发到通过 Tailscale 或局域网可以访问到的另一台设备——适用于
  这台主机有公网 IP、而目标设备没有的场景。可以在控制台中添加、启用、禁用和
  删除转发规则；每条规则在生效前都会与这套安装已经占用的所有端口（控制台、
  公开页面、iperf3、anytls）逐一核对，避免冲突。规则底层依靠 `iptables` 的
  DNAT 加 MASQUERADE 实现，并且每次服务启动时都会自动重新应用，因此重启服务
  或重启主机后，所有已启用的转发都会原样恢复，而不会丢失。首次需要用到时，
  `net.ipv4.ip_forward` 会被自动开启。将 `VPSSRV_PORTFWD_ENABLE=0` 可以把这项
  功能从某次安装中彻底移除。

## v1.0.4 — 2026-09-12

### Changed

- 安装器结尾的摘要信息现在会打印本机的真实 IP 地址，而不再是此前那个必须手动
  替换才能让链接可用的字面占位符 `<this-server>`。内核实际会用来对外发送流量的
  那个地址会出现在公开页面和控制台的行里；在多网卡主机上，其余每个地址会列在
  下方，并各自标注所属网卡，这样一个只能通过 ZeroTier 或 Tailscale 访问到的
  节点也能被直接看到，而不用去猜。如果读取不到任何地址，则会像以前一样打印
  旧的占位符，这样不会因为这点外观问题而让原本顺利的安装失败。

## v1.0.3 — 2026-09-12

### Fixed

- 即便打上了 v1.0.2 的修复，`install_iperf3()` 仍然可能失败。`apt-get update`
  可能报告成功，但 `security.debian.org` 的 CDN 却返回了一份过期的软件包索引，
  于是紧接着执行的 `apt-get install` 在尝试获取索引刚刚宣称存在的那个 `.deb`
  时报 404——这在一台真实主机从 v1.0.1 升级到 v1.0.2 时实际发生过。仅仅单独重试
  `update` 并不能可靠地解决这个问题，因为重试也可能命中同一个过期的边缘节点。
  安装器现在会把 update-then-install 这一整对操作一起重试，最多重试 3 次，
  只要后续某次尝试落到了一个已同步的镜像上就能恢复正常。
- README 的 `## Install` 小节此前仍留有未填写的模板占位符——一个字面意义上的
  `<repo-url>`，以及一个本项目实际上从未发布过的示例标签 `v0.1.0`。两处现在
  都已换成真实值:项目实际的 GitHub URL，以及它当前的发布标签。

## v1.0.2 — 2026-09-12

### Fixed

- `install.sh` 可能会悄悄安装 iperf3 失败:它把 apt 的 update 和 install 两个步骤
  串联在一起，并把所有输出都丢弃了，因此只要有一个无关的仓库出问题——例如某个
  过期的第三方 `.list` 文件，这正是在一台真实 VPS 上实际发生的情况——就会导致
  update 步骤失败，进而整个跳过安装 iperf3，且完全看不出原因。现在会重试 update，
  无论 update 是否成功都会尝试执行 install，并且当 install 确实失败时不再隐藏
  apt 自身的错误输出。

## v1.0.0 — 2026-09-12

首个发布版本。它合并了两个既有项目——一个带密码保护的 VPS 测速控制台，
和一个 sing-box `anytls` 安装器——并新增了两者都不具备的两项能力：
按需开启的 iperf3 测试窗口，以及一个供任何人检测你的 IP 是否在 Web 端口上有响应的公开页面。

### Added

- **80 和 443 端口上的公开可达性页面，无需登录。** 把 IP 给别人；如果页面能渲染出来，
  就说明你的 Web 端口在对方所处网络能被访问到。页面会报告对方的来源地址、
  服务器时钟，以及对方是通过哪个端口和协议访问进来的——除此之外不透露关于主机的任何信息。
  同时提供两个端口的服务是刻意设计:这样才能区分出"主机整体不可达"和
  "443 端口单独被封锁"这两种情况。
- **按需开启的 iperf3 测试窗口。** 控制台会开启一个限时窗口；`iperf3` 只在窗口内运行,
  会在当前生效的防火墙上开放对应端口,并在窗口到期时——无论是用户主动请求关闭,
  还是服务本身停止——把两者一起关掉。没有"一直开着"这个选项，因为一个常开的
  iperf3 服务端会让任何陌生人都能把上行带宽跑满。窗口开启期间，公开页面会显示这一信息，
  方便测试者知道何时可以连接。
- **浏览器测速与访客日志**，控制台内提供:使用 LibreSpeed 引擎的上传/下载测速，
  以及从内核连接表中读取的、记录任意端口（不仅限于 HTTP）上每一次入站 TCP 连接的日志。
- **anytls 代理模块。** 基于自签名证书的 sing-box，配合 BBR。控制台会显示该节点的端口、
  密码和 SNI，提供带一键复制按钮的 Clash 配置条目和 `anytls://` 链接，并支持轮换凭据。
- **可选择模块的安装器。** web、iperf3 和 anytls 三个模块可以独立选择安装，
  既支持交互式选择，也支持通过 `VPSSRV_MODULES` 用于无人值守安装。当端口已被
  其他进程占用时，安装器会拒绝安装而不是去争抢端口；在非 x86-64 架构上会跳过 anytls，
  而不是安装一个根本无法运行的二进制文件。
- **感知升级的重新安装。** 重新运行安装器时会检测到已有安装，提示是否保留其现有配置，
  重放服务单元中记录的设置，保留 anytls 节点的凭据，并且只询问已安装版本当时
  还不存在的那些设置项。对于早于这套配置记录机制的旧安装，则通过读取磁盘上的
  模块列表来处理。
- **三种界面语言**——英语、简体中文、繁体中文——在安装时选择，可在每次访问时切换，
  并会被记住。
- **离线安装。** sing-box 二进制文件随代码仓库一起提供，因此安装除了你所用发行版
  自带的软件源之外不需要任何其他东西。

### Notes

- 整个项目采用 GPL-3.0 许可，因为它重新分发了 GPL-3.0 许可的 sing-box 二进制文件。
  各组件的许可证以及 GPL 要求提供的对应源码链接都列在 `THIRD_PARTY_NOTICES.md` 中。
- 443 端口上的 TLS 是自签名证书:没有域名，也没有 ACME。浏览器发出的警告本身
  恰好证明该端口有响应，而这正是这个页面要解决的问题。
- iperf3 JSON 输出中的 `mean_rtt` 字段来自内核的 `TCP_INFO`，因此 Linux 客户端能报告
  往返时延，而无法读取该信息的客户端——例如 Windows 上 Cygwin 环境下的 iperf3——则
  只能报告吞吐量。UDP 模式（`-u`）在任何环境下都能提供抖动和丢包数据。
- anytls 模块仅支持 x86-64。web 和 iperf3 模块与架构无关。
