**进行中：** v1.1.1 已发布。修复了 README 安装章节的问题——一键安装命令和分步安装命令里都仍然写着 `--branch v1.0.4`，导致 v1.1.0 发布后按此操作的人会装到上一个版本，完全错过端口转发功能。目前没有正在进行中的工作。

发布历史，按时间从新到旧排列：v1.1.0 新增了由控制台管理的端口转发——让控制台把本机上的一个公网 TCP/UDP 端口转发给通过 Tailscale 或局域网可达的一台设备，通过 iptables DNAT + MASQUERADE 实现，规则以 JSON 形式持久化，并在每次服务启动时被幂等地重新应用。在交由运维人员自测之前已自行验证：119/119 个单元测试通过，并且在一次性搭建的三容器 Docker 测试环境中确认了真实 TCP 和 UDP 流量的端到端转发、`net.ipv4.ip_forward` 会自动开启、禁用/启用会立即切换可达性、连续两次重启进程不会产生重复的 iptables 规则，以及一次干净的停止会撤销每条规则在内核中的状态——即便此时 `portfwd.json` 仍写着 `enabled: true`，下次启动也能直接把它恢复回来。运维人员随后在真实主机上手动验证了这一功能。v1.0.4 让安装脚本结尾的总结信息改为打印本机的真实地址——此前它会把地址位置原样打印成 `<this-server>` 占位符，导致其中每个 URL 在使用前都得手动改一遍。v1.0.3 让 `install_iperf3()` 把"更新再安装"这一整对操作一起重试（`apt-get update` 报告成功后，过期的 `security.debian.org` 索引仍可能导致安装 404），并补上了 README 中未填写的 `<repo-url>`/`v0.1.0` 安装占位符；v1.0.2 修复了 `install_iperf3()` 在一个不相关的 apt 源导致 `apt-get update` 失败时会整个跳过安装的问题；v1.0.1 修复了 CHANGELOG 中维护者注释在更新日志页面上的渲染问题——仅影响显示效果，其余不受影响。

在 v1.0.0 之前，运维人员已在真实主机上验证了每一项功能：公开页面在两个公开端口上均可响应，控制台和浏览器测速均正常工作，iperf3 测速窗口在局域网内测得 2.8 Gbit/s，并在窗口关闭后自行拒绝连接，anytls 节点可正常安装、轮换凭据并干净地拆除，升级操作能够在不影响该节点的情况下重放已记录的设置，且三种界面语言均能正常渲染。目前没有正在进行中的工作。
**下一步：** 决定是否需要把共享的 `_db_lock` 解耦——每次命中公开页面都会占用一把进程级的锁并执行一次同步的 SQLite 写入，而控制台也共用这把锁，因此理论上匿名流量的高并发有可能拖慢已认证页面的响应速度。**已实测但未能复现**：60 个并发的高频请求下，控制台延迟保持在 0.4–0.6 毫秒，与空闲状态一致。之所以记录下来，是为了避免这个机制日后被当作新问题重新发现；在没有能证明其确有危害的实测数据之前，不要为此重新设计架构。
**已知问题：** 没有会破坏功能的问题。`BACKLOG.md` 中有四项是主动选择保留、而非缺陷：一是共享的 SQLite 锁，其所报告的负载影响未能复现；二是启动和关闭时的两处信号边界情况；三是单独设置 `VPSSRV_MODULES=iperf3` 时不会安装任何东西；四是缺少登录限速。
**阻塞于：** 无。
