需求清单。所有被提出过的要求，按重要性从高到低排列，做完就打勾。这是那份在隔了两周之后回答"接下来该做什么"的文件，也是一个会话在还有工作没做完时结束后，需求该去的地方。

**`STATUS.md` 的 `Next:` 字段是最上面那条未打勾的条目，原样照抄。** 那一步做完后，在这里打勾，并把下一条未打勾的条目提到 `STATUS.md` 里去。这两处绝不能对不上：`Next` 是跨项目总表展示的那一行，本文件才是恢复工作时真正要读的。

每条都带上加入日期，这样一年前就开着的条目会明显地显得陈旧，而不是悄悄变成永久性的：

```
- [ ] YYYY-MM-DD <要做什么> — <从哪里入手：文件、命令，或悬而未决的问题>
- [x] YYYY-MM-DD <一条已完成的>
```

写条目时要让人能"冷启动"直接开始。"改进错误处理"是一条笔记，不是一条 backlog 条目；"把 mount 调用包进重试逻辑 —— `src/mount.py`，末尾那个裸 `except`"才是。
