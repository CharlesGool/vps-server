# 決策記錄

[English](../DECISIONS.md) | **繁體中文**

> 譯自 `DECISIONS.md`（v1.0.0）。如有衝突，以英文版為準。

這不是一份決策日誌，而是用來防止重新提案的機制。判斷一件事該不該收進來，只看一個問題：

> 六個月後，我或另一個 agent 會不會把這個當成新點子重新提出來？

會 → 收一條。不會 → 不收，那不算遺漏。「我們用 PostgreSQL」屬於 DESIGN.md；
「評估過 MongoDB，因為 X 而否決」才屬於這裡。

**每條決策最多五行條列，內文控制在約 1000 bytes 以內。** 兩個上限都要守，不是二選一：
只設行數上限沒有約束力，因為目前量過最大的檔案裡，大多數也就是五行的條目，
每行卻是一整段沒換行的文字。超過這個上限就是 DESIGN.md 的材料——搬過去。

這個上限是讓這份檔案能維持可用的關鍵。每條決策佔到 2 KB，就沒人會在提案前先打開來看，
一份沒人讀的防線等於沒有防線。

由新到舊排列，只增不刪。要推翻某個決策，就新增一條說明推翻的理由——
絕不編輯或刪除舊的那條。

## 2026-09-12 — 公開頁面與後台控制台是兩個獨立的監聽器，各有各的處理類別

- **Rejected:** 用同一個監聽器同時服務兩者，後台路由靠路徑前綴加驗證來把關——驗證機制可能因為 bug 而放行；一個根本不存在的路由則不可能。
- **Rejected:** 把後台控制台本身也放到 80/443、靠密碼保護，捨棄原本的隨機通訊埠——這樣會丟掉 `vps-webserver` 當初刻意選用的隱蔽層。
- **Cost:** 同一個行程裡跑三個監聽器，而且兩個處理類別各自都要接上訪客紀錄的掛鉤。
- **Do not re-add this as an improvement.**

## 2026-09-12 — iperf3 只在操作者手動開啟、有時限的視窗內運作

- **Rejected:** 常駐開放的公開 `iperf3 -s`——任何陌生人都能無限期地把上行頻寬吃滿，而且沒有任何跡象會顯示正在發生這件事。
- **Rejected:** 常駐開放但搭配 `--authorized-users-path` 做 RSA 驗證——測試前必須先透過帶外管道把憑證交給對方，這等於違背了「把 IP 給對方、讓他自己測」的初衷。
- **Cost:** 遠端測試者無法在無人看管的情況下自行測試；必須有人先開啟視窗。公開頁面會宣告目前有開放中的視窗，讓測試者知道何時可以連線。

## 2026-09-12 — 通訊埠 443 使用自簽憑證，不接 ACME，也不掛網域

- **Rejected:** 對真實網域跑 certbot / acme.sh——這個頁面存在的目的是回答「這個 IP 能不能連得到」，瀏覽器的憑證警告頁本身就已經證明了可連通性。為了這個問題去依賴網域名稱、還要維護憑證更新計時器，換不來任何好處。
- **Rejected:** 只服務通訊埠 80——這樣就無法區分「主機根本連不到」和「443 這個埠specifically被擋」，而後者正是值得偵測的常見情況。
- **Cost:** 每次以 HTTPS 造訪都會跳出憑證警告。這是預期行為；不要用 HSTS 或釘住例外憑證去「修掉」它。

## 2026-09-12 — sing-box 執行檔隨儲存庫一起發布，因此整個專案採用 GPL-3.0

- **Rejected:** 在安裝時才下載 sing-box，藉此讓儲存庫保持精簡、授權維持 Apache-2.0——`Anytsl-Serve` 先前就已經否決過完全相同的做法，理由是要讓安裝流程不依賴 GitHub 存取；在這裡重新決定一次，等於默默推翻那個既定目標。
- **Rejected:** 拿掉 anytls 模組，藉此保留 `vps-webserver` 原本的 Apache-2.0——當初的需求是把兩個專案合併起來，不是二選一。
- **Cost:** git 儲存庫因此多出約 57 MB，且會隨每次 sing-box 版本更新持續增加；此外 `vps-webserver` 原本 Apache-2.0 授權的程式碼，在這裡是以 GPL-3.0 重新發布。

## 2026-09-12 — 上游專案採用 vendor 方式內嵌，既不取代也不設為 submodule

- **Rejected:** 讓 vps-server 直接取代 `vps-webserver` 和 `Anytsl-Serve`、並把兩者都封存——三者要維持各自獨立維護、各自獨立發布。
- **Rejected:** 用 git submodule 指向這兩個上游儲存庫——submodule 無法承載這個專案所需的改名（unit 名稱、執行檔名稱、`VPSWS_` → `VPSSRV_`），而且這樣一來 clone 時還得額外連線去存取另外兩個儲存庫。
- **Cost:** 同一份程式碼會同時存在於三個儲存庫裡，並隨時間產生落差。緩解方式：`.upstream-version` 檔案會記錄每份 vendor 進來的程式碼確切對應的上游 tag，往後每次更新都必須在同一個 commit 裡一併更新這份記錄。
